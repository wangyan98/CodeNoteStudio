Implementation Approaches

Two strategies for adding drag-and-drop @ref creation

Approach A: Lightweight HTML5 DnD
Interaction Flow
Code Viewport
getUserById
double-click → highlighted
→ drag →
Note Viewport
@ref(src/utils.ts:42:getUserById)
inserted at cursor
What the user sees
  • Double-click → function name gets a blue highlight
  • Drag → browser default ghost (transparent copy of the highlighted text)
  • Drop → @ref appears at cursor position in MdEditor
  • Code Directory: drag a file → [filename](rel/path) or ![img](./assets/img.png)
Architecture
CodeViewport
├─ Monaco decoration (highlight)
├─ onMouseDown → detect dbl-click → IPC querySymbol
└─ HTML5 draggable on editor container

CodeDirectory
└─ draggable="true" on file items

NoteViewport
└─ onDrop → screen coords → Monaco position → insertText

Main Process
└─ IPC: copy-file-to-assets (for images)

Pros

  • ~150 lines of new code
  • Follows existing CustomEvent pattern
  • No new dependencies or context providers
  • Browser-native drag, works reliably

Cons

  • Default drag ghost looks basic
  • No drop-zone indicator in NoteViewport
  • User must guess where @ref will land
Approach B: Rich DnD with Visual Feedback
Interaction Flow
Code Viewport
getUserById
double-click → pill appears
→ drag →
Note Viewport
drop indicator ▏
shows where text lands
What the user sees
  • Double-click → a fn getName pill appears beside the line
  • Drag → custom drag ghost: same pill follows cursor
  • Hover over NoteViewport → drop zone highlight with a cursor-line indicator
  • Code Directory drag → shows file-type-specific ghost (📄 file vs 🖼 image)
  • Drop → smooth insertion with a brief flash animation on the inserted @ref
Architecture
DragContext (new React context)
├─ dragState: { source, symbol, ghostElement }
├─ onDragStart / onDragEnd
└─ consumed by all 4 panels

CodeViewport
├─ Monaco decoration + floating pill component
└─ uses DragContext.startDrag()

NoteViewport
├─ DropZone wrapper component
├─ shows insertion line indicator on dragover
└─ uses DragContext.onDrop()

Main Process
└─ IPC: copy-file-to-assets (for images)

Pros

  • Polished, professional feel
  • Clear affordance at every step
  • No guesswork about where text lands

Cons

  • ~400+ lines of new code
  • New DragContext adds complexity
  • Floating pill positioning is fiddly
  • More surface area for bugs

My Recommendation: Approach A

Given that the user already chose the simplest selection style (C: inline highlight) and the simplest file reference format (B: standard markdown link), Approach A aligns with the pattern of keeping things minimal. The default browser drag ghost is adequate for an initial implementation, and we can always add visual polish (drop indicators, custom ghosts) later without changing the architecture.
