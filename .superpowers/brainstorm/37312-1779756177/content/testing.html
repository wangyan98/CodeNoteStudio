Edge Cases & Testing

Error handling and verification strategy

Edge Cases

Scenario Behavior
Last workspace path deleted/moved Show landing page, prompt to select new folder
Workspace folder has no write permission Alert: "Cannot open workspace — read-only folder"
notebook.json is corrupted (invalid JSON) Load defaults, warn: "Config corrupted, using defaults"
Repo path no longer exists Gray out the repo chip, show tooltip "Path not found"
Add duplicate repo path No-op or show brief toast "Already linked"
First launch (no workspace.json yet) Show landing page — same as deleted path
notesPath in config points to missing dir Create the directory on load (mkdir recursive)
User cancels folder picker dialog Stay on current workspace or landing page

Testing Strategy

Unit Tests (vitest)

  • workspace.ts — read/write workspace.json, path validation
  • notebook-config.ts — load/save with default fallback
  • WorkspaceToolbar — renders landing page vs toolbar based on workspace state
  • CodeDirectory — renders multiple repos, empty state

Integration Tests

  • IPC: workspace:open → loads config, persists path
  • IPC: dialog:select-folder returns path or null
  • IPC: workspace:get-current returns current path
  • Full flow: open workspace → create note → verify on disk

Changes NOT in scope

  • Multiple simultaneous workspaces (single-workspace model)
  • Drag-and-drop folder to open (landing page shows text hint only)
  • Workspace-level settings beyond notebook.json
  • LSP integration
  • "Recent workspaces" list (last path only, for now)
