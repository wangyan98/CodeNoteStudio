Core types (replacing current NetworkDocument)

src/main/schemas/note-types.ts — new or heavily modified types
// ---- Node types ----

type NodeKind = 'input' | 'output' | 'layer' | 'block'

interface GraphNode {
  id: string
  kind: NodeKind
  label: string                // display name
  // kind-specific:
  layerType?: string           // 'Conv2d', 'ReLU', etc (kind='layer')
  params?: LayerParams         // (kind='layer')
  inputShape?: string          // annotated tensor shape
  outputShape?: string
  repeat?: number              // block repeat count (kind='block')
  children?: GraphNode[]       // nested nodes inside this block
  internalEdges?: GraphEdge[]  // edges inside this block
  codeMapping?: CodeMapping    // reuses existing type
  x?: number; y?: number       // optional manual override position
}

// ---- Edges ----

type EdgeStyle = 'forward' | 'skip'

interface GraphEdge {
  id: string
  source: string               // node id
  target: string               // node id
  label?: string               // tensor shape annotation on the arrow
  style: EdgeStyle             // forward=solid straight, skip=dashed curved
}

// ---- Document ----

interface NetworkDocument {
  type: 'net'
  version: 2                   // bumped from v1
  name: string
  nodes: GraphNode[]
  edges: GraphEdge[]
  inputShape?: string          // migrated: becomes input nodes, kept for backwards compat
}

Key changes vs current

What we gain

  • nodes[] is one flat list — input, layer, block all in the same space
  • edges[] is one flat list — no distinction between "sequential", "connection", "skipConnection"
  • Edge style (forward vs skip) is purely visual, not structural
  • Block stays as a node kind — can contain nested children for hierarchical grouping
  • Every node can have 0-N inputs and 0-N outputs — no restrictions

What we lose

  • No more implicit sequential connections — users must create every edge
  • v1 .net.json files need a migration path
  • Data model is more verbose for simple linear networks
