Which DSL format should we use?

Since we chose a text-based approach, the key decision is which syntax the user writes in

A

Mermaid syntax — .seq.mermaid or .seq.md

Use Mermaid.js syntax for sequence diagrams. It's the most popular open-source diagramming DSL, well-documented, and has an existing JS renderer library.

sequenceDiagram
  Alice->>Bob: Hello Bob!
  Bob->>Alice: Hi Alice!
  Alice->>Server: Request
  Server-->>Alice: Response

Pros

  • Familiar syntax, large community
  • Mermaid.js renderer exists and is maintained
  • Can render to SVG in browser

Cons

  • Need to bundle mermaid.js (~1MB)
  • Mermaid's sequence diagram syntax has limitations (no nested fragments in some versions)
B

PlantUML syntax — .puml

Use PlantUML syntax, rendered via a PlantUML server or WASM. More feature-rich than Mermaid for sequence diagrams.

@startuml
  Alice -> Bob: Hello
  Bob --> Alice: Hi
  Alice -> Server: Request
  Server --> Alice: Response
@enduml

Pros

  • More sequence diagram features (grouping, notes, etc.)
  • Industry standard in some domains

Cons

  • Requires PlantUML server or WASM binary
  • Heavier dependency
  • Less JS-native than Mermaid
C

Custom simple DSL — .seq

Design a minimal custom syntax, purpose-built for this app. Rendered with a custom lightweight renderer (SVG/Canvas).

participant Alice
participant Bob
participant Server

Alice -> Bob: Hello
Bob -> Alice: Hi
Alice -> Server: Request
Server -> Alice: Response

Pros

  • Full control over syntax and features
  • Tiny bundle size
  • Can be optimized for this exact use case

Cons

  • Build everything from scratch
  • No community resources or documentation
  • Users learn a proprietary syntax
