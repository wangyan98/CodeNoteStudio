How should layer types and their parameters be defined?

The system needs to know: which layers exist, what params each takes, and how they render visually

A

Built-in TypeScript catalog

// src/main/schemas/layer-catalog.ts
export const LAYER_CATALOG: Record<string, LayerDef> = {
  Conv2d: {
    category: 'convolution',
    color: '#4a90d9',
    params: [
      { name: 'in_channels', type: 'number', required: true },
      { name: 'out_channels', type: 'number', required: true },
      { name: 'kernel_size', type: 'number|tuple', default: 3 },
      { name: 'stride', type: 'number|tuple', default: 1 },
      { name: 'padding', type: 'number|tuple', default: 0 },
      { name: 'dilation', type: 'number|tuple', default: 1 },
      { name: 'bias', type: 'boolean', default: true },
    ],
    tensorShapes: {
      input: '(N, C_in, H, W)',
      output: '(N, C_out, H_out, W_out)',
    }
  },
  BatchNorm2d: {
    category: 'normalization',
    color: '#ea4335',
    params: [
      { name: 'num_features', type: 'number', required: true },
      { name: 'eps', type: 'number', default: 1e-5 },
      { name: 'momentum', type: 'number', default: 0.1 },
    ]
  },
  // ... Linear, ReLU, MaxPool2d, Dropout, etc.
}

Pros

  • Type-safe — autocomplete in editor
  • Simple — no extra file I/O
  • Deterministic — same for all users

Cons

  • Only PyTorch layers supported
  • Adding layers requires code changes
B

JSON registry — user-extensible

// notes/.layer-catalog.json (at workspace root)
{
  "layers": {
    "Conv2d": {
      "category": "convolution",
      "color": "#4a90d9",
      "params": [
        {"name": "in_channels", "type": "number"},
        {"name": "out_channels", "type": "number"},
        {"name": "kernel_size", "type": "number|tuple", "default": 3}
      ]
    },
    "MyCustomLayer": {
      "category": "custom",
      "color": "#9c27b0",
      "params": [
        {"name": "hidden_dim", "type": "number"}
      ]
    }
  }
}

Pros

  • Users can define custom layers
  • Per-project layer definitions
  • Easy for agents to extend

Cons

  • No type safety
  • Must validate registry at load time
  • Layer names may differ across projects
C

Hybrid: built-in defaults + project overrides

// Built-in: full PyTorch catalog (shipped with app)
// src/main/schemas/layer-catalog.ts (Option A above)
// Covers: Conv2d/1d/3d, Linear, BatchNorm, LayerNorm,
//          ReLU/GELU/SiLU, MaxPool, AvgPool, Dropout,
//          Embedding, LSTM, Transformer layers, etc.

// Optional per-project overrides:
// notes/.layer-catalog.json
{
  "extend": {
    "MyCustomAttention": {
      "category": "attention",
      "color": "#ff9800",
      "params": [{"name": "dim", "type": "number"}]
    }
  },
  "override": {
    "Conv2d": {
      "color": "#1565c0"  // darker blue for this project
    }
  }
}

Pros

  • Comprehensive PyTorch catalog out of the box
  • Type-safe for built-in layers
  • Custom layers when needed
  • Per-project color overrides

Cons

  • Slightly more code (merge logic)
