JS UI + C++ 性能的混合架构

三种方式把 JS 生态和 C++ 结合起来

A

Electron + C++ Native Addon (推荐)

Electron 做壳和 UI，C++ 通过 node-addon-api (N-API) 编译为 Node 原生模块直接内联到 Electron 主进程。单进程，JS ↔ C++ 调用零延迟。

JS 端：Monaco Editor / D3.js / Markmap / KaTeX
C++ 端：tree-sitter 解析 / LSP client / 文件监控 / 高性能索引
通信：直接函数调用（N-API），无需 IPC

✅ 架构最清晰：UI 全在 JS，计算全在 C++，边界明确

B

Electron + C++ 独立进程

Electron 做 UI 壳，C++ 编译为独立后台进程，通过本地 WebSocket 或 Unix Socket 通信。两个进程可独立开发调试。

JS 端：同上
C++ 端：独立可执行程序，功能更完整
通信：JSON-RPC over WebSocket

⚠️ 多一层 IPC 开销，但 C++ 进程可独立测试和复用

C

Qt + QtWebEngine (C++ 为主)

不用 Electron，用 Qt + QtWebEngine（也是 Chromium 内核）。C++ 是主进程，UI 通过嵌入 Web 页面实现。C++ 和 JS 通过 Qt WebChannel 双向通信。

没有 Node.js 层，更轻量。但 Qt 的 JS 生态不如 Electron 便捷，npm 库需要手动引入。

✅ 包体积更小，C++ 天然主导，但前端工具链需要额外配置
