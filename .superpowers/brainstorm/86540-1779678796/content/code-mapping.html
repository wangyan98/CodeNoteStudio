代码函数映射机制

笔记节点怎么"知道"它关联了哪个代码函数？

A

手动声明 + 静态索引

用户在手记节点中写 @map: quicksort 或点击「关联」按钮选择函数。app 提前用 tree-sitter/ctags 解析代码仓库生成函数索引表，用户从列表中选择。

优点：精确可控，实现简单
缺点：代码重命名后映射断裂

B

手动声明 + LSP 实时感知

类似 A，但通过 LSP 实时连接代码仓库。代码中函数重命名/移动时，映射自动更新。需要 LSP server 运行。

优点：映射可追踪代码变更
缺点：依赖 LSP，复杂度高

C

手动声明 + git commit 锚点不追踪

映射以函数名 + git commit SHA 为准。代码视口展示的是该 commit 时的代码快照。函数名是"在那个时刻"的标识，不追踪重命名。

优点：笔记永远指向一致的代码版本
缺点：更新映射需要手动切换到新 commit
