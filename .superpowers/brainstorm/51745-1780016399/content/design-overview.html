Multi-Repo Support — Design Overview

Architecture, data flow, and UI changes for proper multi-repo support

Architecture Overview

1. DB Schema Change
CREATE TABLE symbols (
  ...existing columns...,
  repo_path TEXT NOT NULL
)

CREATE INDEX idx_repo_path ON symbols(repo_path)

Add repo_path column. Index on repo for fast scoped queries.

2. Indexing — Per-Repo, No Cross-Contamination
indexRepo(repoPath):
  DELETE FROM symbols WHERE repo_path = ?
  parse files in repoPath
  INSERT INTO symbols (..., repo_path) VALUES (..., repoPath)

Each repo independently indexed. Deleting only that repo's rows before re-insert.

3. @ref Format — Repo-Scoped
New:   @ref(backend:src/main.go:42:HandleRequest)
Legacy: @ref(src/main.go:42:HandleRequest) → scoped to active repo
4. Resolution — Repo-First, Then T1-T5
resolveRefs(refs, allSymbols, activeRepo):
  // New: has repo prefix
  if ref.repo:
    candidates = symbols.filter(s => s.repo_path ends_with ref.repo)
  // Legacy: no repo prefix
  else:
    candidates = symbols.filter(s => s.repo_path ends_with activeRepo)
  apply T1-T5 matching within candidates
